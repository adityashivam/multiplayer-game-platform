# Sky Dash Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement the independent tasks below. Track checkable steps and verify behavioral contracts before completion.

**Goal:** Deliver a responsive original 3D obstacle race with two human seats, three bots and standard platform controls.

**Architecture:** Game-owned course/rules/rendering adapt to existing authoritative input and browser network session SDKs. A focused reusable kinematic character module owns movement and platform contact. Human seats, bots and runtime quality remain configurable.

**Tech Stack:** JavaScript ES modules, existing Three.js, Socket.IO, Node test runner, platform React shell.

**Spec:** [Sky Dash design](../specs/2026-11-08-sky-dash-design.md).

## Global Constraints

- Two human seats and three bots by default; no additional dependencies or hosting changes.
- Preserve stable shell geometry, configurable touch controls and explicit browser presentation choices.
- Keep simulation pure, bounded and server-authoritative; integrate through existing platform contracts.
- Use meters, seconds, Y up, negative Z course direction and bottom-of-collider Y.
- Do not commit or deploy without a request.

## Review Focus

- Short presses, simultaneous sources and modal focus must not lose edges or leave inputs held.
- Fast dash/contact, standing on a moving platform and crossing platform edges must not tunnel or jitter.
- Fall respawns and reconciliation must not drag racers across the course or admit checkpoint shortcuts.
- Rejoin, rematch and slot saturation must preserve ownership and round state without ghost bots or stale input.
- Portrait/small hosts and quality changes must preserve canvas, readable HUD and standard shell controls.

## Tasks

### 1. Pure reusable character physics

Files: `public/platform/shared/kinematicCharacter.js`, `tests/kinematic-character.test.js`.

Interface: `createKinematicCharacterController(settings).step(body, {x,z,jump}, dtSec, {platforms,controlScale?,speedScale?})`; body includes x/y/z, vx/vy/vz, grounded, supportId, coyoteSec, jumpBufferSec, jumpHeld. Platforms use numeric id, center x/z, width/depth, topY, thickness, vx/vy/vz. `resolveKinematicCharacterSeparation(bodies, settings)` handles overlapping vertical characters. No concrete game imports.

- [x] Write failing tests for landing, jump buffering/coyote, analog normalization, fast side contacts, undersides, moving support and separation.
- [x] Implement bounded substeps, stable support and contact response; verify tests including a differently configured character.

### 2. Game rules, bots and authoritative registration

Files: `public/games/sky-dash/shared/{config,course,simulation}.js`, `server/platform-backend-engine/games/sky-dash.js`, `tests/sky-dash-{simulation,pipeline}.test.js`.

Interfaces: shared input `{moveX,moveZ,jump,dash,dive}`; numeric axes in [-1,1]. `createSkyDashRound({playerIds?,botCount?})`, `createSkyDashRunner(id,slotIndex,isBot)`, `stepSkyDashRunner(runner,input,dtSec,{active,timeSec})`, `stepSkyDashWorld(round,dtSec)`, `createSkyDashBotInput(round,bot)`. Round snapshots own `players`, `bots`, `timeSec`, `timer`, `started`, `startAt`, `gameOver`, `winner`, `roundId`; runners own id/name, position/velocity, grounded support fields, progress/checkpoint, action/timers, connected/finished/finishTimeSec/rank/respawn identity.

- [x] Write failing rules tests for distinct actions, obstacle hit/overlap, respawn/checkpoint fairness, idle and bot race completion, configurable capacity, results and countdown pause.
- [x] Implement game rules over the character controller and SDK input sessions; no hand-rolled networking.
- [x] Verify snapshot shape, full/delta encoding, pause/rejoin/rematch and no bot seat consumption.

### 3. Renderer

Files: `public/games/sky-dash/rendering/*.js`.

Interface: `createSkyDashRenderer({canvas})` returns `resize`, `setQuality`, `render({dtSec,timeSec,courseTimeSec,playerId,runners,reducedMotion,cameraOrbit})`, `getStats`, `dispose`. Runners supply all game state including x/y/z, yaw, vx/vy/vz, grounded, action/actionTimeSec, hitSec, respawnId, finished, colorIndex. Analytic obstacle/course sampling comes from shared course config.

- [x] Build full course, expressive original runners and follow camera using real geometry; authored procedural clips distinguish running/jumping/dashing/diving/tumbling/finishing.
- [x] Keep pooled effects/resources bounded, reset camera on respawn, honor render quality and dispose all owned resources.
- [x] Verify actual browser composition and movement at landscape and portrait host sizes.
